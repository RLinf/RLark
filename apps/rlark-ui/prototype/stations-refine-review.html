先看什么

这一轮解决的是 2000 宽显示器上「卡片少、面板宽、右侧大片空」的问题。请在右上角切到 方向 A 和 方向 B，用它们页面内置的 2000 / 1440 / 390、亮暗、中/EN 开关逐个对比（原型自带控件，均为静态演示数据，不发真实请求）。

当前生产的问题（截图 Image #34 时点）

  • 面板全宽无上限：机器人 3 张卡后空出第 4 列（约 430px），库存 2 张卡后空约 920px。
  • s1u-01 因「回位不可用」提示把页脚撑高约 18px，同行卡片底部不齐，展开按钮被挤到第二行。
  • 工具栏搜索近半宽、计数跑中间、「加入节点」贴边；页签条撑满只用 40%；分区标题与卡片标题同字号。
  • 控制面条 / 批量行 / 卡片网格三种宽度；库存第二集群多一条重复分隔线。

方向 A · 对齐与密度（node-removal Codex）

  • 1480px 内容列；机器人固定 3 列 ×460、库存 4 列 ×360（窄宽降 3/2/1）。
  • 展开按钮移到卡片头部右侧（icon）；机器人页脚固定两行：操作 + 16px 提示槽，同行卡片底部严格对齐；库存卡去掉页脚。
  • 页签左对齐收窄、工具栏一行 40px 控件、分区标题层级化；不新增任何信息块。

方向 B · 构图与信息（station-cluster Codex）

  • 沿用 A 的卡片契约（1480 列、3×460 / 4 列库存、header 展开、页脚提示槽）。
  • 库存行没满时用「集群摘要」卡补满剩余轨道：在线比例条、节点/入网/驱动/相机统计，链接到入网记录；满行时不渲染。
  • 集群头部加统计条；首版省略了页面级右栏，保卡片宽度。

注意

  • 两版相机器画面均为示意帧（A 为插画式示意，B 为参考截图帧），生产里是真实慢速预览。
  • 电源/驱动/回位/记录操作均为本地模拟，只验证交互形态，不下发命令。

A 评 B（node-removal → station-cluster）

总分 26/35。优点：1480 居中列、末行摘要与网格右缘重合（717px/0px 偏差）、详情/相机/回位/电源交互闭环全部实测通过、token 无未定义项。

P2 缺陷：

  • 组头统计与摘要卡重复（在线/冲突/节点/入网两处都出现）——摘要应只留健康条 + 一个有决策价值的异常指标 + 入网入口。
  • 库存轨道实测 352.5px（1440 下 330.5px），没达到 360 契约——padding/gap 挤压，需重新分配。
  • 工具栏「机器人型号」与「加入节点」之间 ~278px 断带——主操作组应连续。
  • 统计口径是「已加载集合」，接生产分页时要区分 loaded/total，未知不能显示 0。

P3：390 英文下集群统计条换行成高块，首卡下移到 y≈754——小屏应收紧为一行短摘要。

B 评 A（station-cluster → node-removal）

总分 18/35。优点：默认卡片对齐/控制密度、亮暗 token 零硬编码、header 展开按钮 + 库存去页脚省空间。

P1（原型行为偏差，多为演示简化所致）：

  • 批量操作把筛选后隐藏的机器人也包含进确认框（全选读全局集合）。
  • 回位在指针移出/键盘失焦后仍保持按住状态。
  • 展开详情把同排其余卡片挤走（整行分块没保住）。
  • 控制面展开无详情面板；库存详情的入网事实与卡片矛盾、操作可用性缺失。

P2：toast 不可关且无 role/焦点丢失、库存末行仍空 732px、宽屏详情第四块落第二行右侧两列空置、相机异常放大态被标绿、四态计数与内容不一致、390 入网表横滚 498px 无提示、英文相机字幕裁切。

注：以上行为项大多源自 A 原型用 innerHTML 整页重绘的演示简化；生产 React 版（CardGrid 分块、useRobotPower、RobotPoseButton、StationDetailPanel）已正确处理这些契约，最终落地以生产组件为准。

基底建议（两边已交，结论一致：混合）

A 的建议：以 A 为布局与交互基底，取 B 的条件摘要。

B 的建议：以 B 的构图为基底，吸收 A 的卡片密度和入网记录表。

两边合并清单其实重合，即最终合成规格：A 的几何骨架（1480 列、3×460、页脚提示槽、工具栏连续操作组、完整入网表字段）+ B 的构图（末行未满时轻量摘要卡、组头「驱动就绪/相机异常」两指标）+ 生产行为组件（CardGrid 分块、useRobotPower、RobotPoseButton、StationDetailPanel 的既有契约——两份互评指出的行为偏差在最终实现里以生产组件为准，不随原型走）。

这个规格就是视觉轮 brief 的骨架：两版在此之上只比视觉层。

需要你拍板

  • 基底方向：A（只做对齐/密度，不加信息块）/ B（对齐 + 库存摘要卡 + 集群统计条）/ 混合。
  • 若选 B/混合：摘要卡只放库存行，还是机器人集群头部也加统计条？
  • 机器人卡片底部 16px 空提示行（对齐用）接受吗？还是只在有话可说时显示、接受 1 行高度差？
  • 展开按钮：卡片头部 icon（两版方向）还是保留页脚文字按钮（当前生产）？
  • 内容列宽 1480px 可以吗？
  • 入网记录表：A 是全列（状态/发码人/时间/公钥/隧道），B 首屏精简为 4 列——取哪边？
