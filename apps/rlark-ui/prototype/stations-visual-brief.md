# 设计语言轮：两个本质不同的方向（不是同一张页面的两种摆法）

## 为什么重出题

上一轮把卡片视觉冻结、只修几何，用户看到的第一反应是「和现在没本质区别」。本轮取消视觉冻结：**每个方向必须换掉页面的设计语言**，第一眼就要和现役页面（截图 34.png：白卡片 + chip 堆 + 边框盒子 + 相机墙）分得开。用户拍的是语言，不是微调。

## 不变的东西（所有方向共用）

- 同一份 mock 数据：3 台机器人（ready / 驱动停 / 相机异常恢复中）、控制面 alexfu、2 台库存节点、3 条入网记录。
- 同一份行为契约：电源/驱动确认 + toast、按住回位（短按提示、阻塞原因）、相机慢预览 + 点击放大、单开详情、Escape/焦点返回、冲突/删除/入网记录入口、无 API 请求。
- 信息量不减：现役页面展示的每项信息都要有去处（可以换形态、换位置，但不能消失）。
- 内容列必须有界（1280–1600 内自选），这是上一轮确认的合理修正。
- 响应式：2000/1440/390 × 亮暗 × zh/en 全过，无横向滚动、无 console error。
- token 仍用 theme-overlay.css 那套变量，但允许在原型内定义新的派生色阶（注明即可）。

## 方向 A「监控墙」（node-removal）

现役页面是「表格思维套上相机」；这个方向反过来：**画面就是界面**。

- 机器人 = 无边框相机 tile：状态、名字、电源直接压在画面上（顶部渐变遮罩 + 左下角文字），健康机器人退后，异常 tile 用 amber/red 描边发光跳出——一眼看到出事的机器人。
- 集群 = 一面墙；控制面与库存节点不再是卡片，是一条紧凑等宽数字表格（namespaced rows、tabular-nums）。
- 气质：安保监控墙 / 转播控制室。暗色优先设计，亮色做到「广播监控墙」而不是反色。
- 详情与操作：点击 tile 进操控层（放大画面 + 四路 + 电源/回位），确认与 toast 照契约。

## 方向 B「去框化清单」（station-cluster）

现役页面精致不起来的根本原因是 chip/边框噪声太大。这个方向做减法：**删掉所有盒子，让排版和留白干活**。

- 没有面板、没有卡片框：集群是标题 + 一列行；机器人行 = 相机小缩略图 + 名字 + 一行彩色状态词 + hover/focus 浮出的行内操作；相机进 lightbox。
- 状态永远是一个色点 + 一个词，全页面禁止 chip 堆；分组靠留白和字阶，不靠 1px 边框。
- 气质：Linear/Notion 的安静清单。宽屏上是从容的列，不是空荡的大盒子。
- 详情：行内展开或侧滑皆可，保持键盘契约。
