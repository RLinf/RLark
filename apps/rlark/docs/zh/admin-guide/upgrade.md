# 集群升级

RLark 支持对数据面集群进行批量升级。通过创建升级任务，可以指定目标镜像和配置，系统会自动在选定的集群上执行升级，并在失败时自动回滚。

## 创建升级任务

进入 **管理后台 → 集群升级**，点击 **创建升级任务**。

### 基本配置

| 字段 | 说明 | 必填 |
|------|------|------|
| 备注 | 描述本次升级的目的，便于后续识别 | 否 |
| 升级镜像 | rlark-upgrade 镜像地址，例如 `registry/rlark-upgrade:v0.0.10` | 是 |
| 目标集群 | 选择要升级的集群，支持多选 | 是 |

### 高级配置

| 字段 | 说明 | 默认值 |
|------|------|--------|
| 并发数 | 同时升级的集群数量 | 1 |
| 失败容忍比例 | 允许的失败集群占比（0-1），超过后中止升级 | 0 |
| 超时（秒） | 每个集群升级的超时时间 | 600 |
| 失败时自动回滚 | 升级失败后是否自动回滚到之前版本 | 开启 |

### 部署配置

这里使用 `rlarkadm` **DeployConfig** 合同，不是 Agent 启动文件（`version: v1` + `options`）。升级从 DeployConfig 重新生成独立的 cluster Deployment 与 node DaemonSet，并重启进程；不会热加载 Agent 启动文件、保留自定义 embedded 拓扑，也不实现 `node-startup=managed`。手动添加的参数或配置文件挂载不会在生成的 workload 替换中保留。自定义启动文件/embedded 部署应使用各自的 rollout 流程，见 [Agent 启动配置](../reference/configuration.md#agent-startup-file-and-validation)。

如需修改 agent 镜像或其他部署配置，在 **部署配置** 中填写 YAML。

**部署配置** 是完整的 `DeployConfig` YAML，用于指定升级后的部署参数。可以将升级过程类比为 Helm Chart 部署：
- **升级镜像**（rlark-upgrade）相当于 Chart 包
- **部署配置** 相当于 `values.yaml`，用于自定义部署参数

```yaml
apiVersion: rlark.io/v1alpha1
kind: DeployConfig
plane: data
control-plane-address: https://rlark-server.rlark-system.svc:8443
kubernetes:
  agent-image: registry/rlark:v0.0.67
  image: registry/rlark:v0.0.67
  image-pull-policy: Always
```

**注意事项**：
- 必须是**完整配置**，包含 `apiVersion`、`kind`、`plane` 等必填字段
- `control-plane-address` 必须填写
- `cert` 字段不需要填写（升级时证书已存在于集群中）
- 如果不需要修改配置，留空即可（使用当前配置）
- 非 Kubernetes 场景（Docker/裸机）也使用相同的配置格式，字段根据部署模式调整

## 查看升级任务

### 任务列表

任务列表按创建时间倒序排列，显示以下信息：

- **任务名称**：自动生成的唯一 ID（如 `up-xxxxx`）
- **状态**：
  - **等待中**：任务已创建，尚未开始
  - **升级中**：正在升级
  - **成功**：所有集群升级成功
  - **已回滚**：部分集群失败但已回滚成功
  - **失败**：部分集群失败且无法回滚
- **进度**：显示成功/失败/回滚的集群数量，如 `2/4 (1 失败, 1 回滚)`
- **创建时间**：任务创建时间

### 筛选与搜索

- **状态筛选**：点击状态列的筛选按钮，可多选显示特定状态的任务
- **搜索**：支持按任务名称或备注搜索

### 任务详情

点击任务名称进入详情页，查看：

- **进度**：各状态集群的占比条
- **任务信息**：备注、升级镜像、目标集群、并发数、超时时间、自动回滚设置
- **部署配置**：本次升级的配置内容
- **集群明细**：每个集群的状态、完成时间、详细信息

## 任务状态说明

### ClusterUpgradeJob（每个集群的执行状态）

| 状态 | 说明 |
|------|------|
| Pending | 等待执行 |
| Upgrading | 升级中 |
| Succeeded | 升级成功 |
| RolledBack | 升级失败但回滚成功 |
| Failed | 升级失败且回滚失败（或回滚未启用） |

### UpgradeJob（整体任务状态）

| 状态 | 说明 |
|------|------|
| Pending | 等待执行 |
| Upgrading | 有集群正在升级中，或有集群已完成但还有未创建的（受并发限制） |
| Succeeded | 所有集群升级成功 |
| RollingBack | 所有集群已完成，部分失败但已回滚成功 |
| Failed | 所有集群已完成，部分失败且无法回滚；或失败容忍度超限 |

**状态优先级**：
1. 有集群升级中 → **Upgrading**（即使有集群失败）
2. 全部完成 → 根据结果定 **Succeeded** / **RollingBack** / **Failed**
3. 未全部创建（并发限制）但有集群已完成 → **Upgrading**

具体每个集群的状态请查看详情页的集群明细。

## 复制创建

如需基于之前的任务快速创建新任务：

1. 在任务列表或详情页点击 **复制创建**
2. 表单自动填充之前任务的配置
3. 修改需要的字段后提交

## 删除任务

只能删除已完成的任务（非升级中/回滚中状态）：

1. 点击任务行的 **删除** 按钮
2. 确认后删除

**注意**：删除任务不会回滚已完成的升级。

## 自动回滚

当 **失败时自动回滚** 开启时，升级过程如下：

1. 升级 Pod 执行升级前检查
2. 升级组件（agent、agent-node 等）
3. 健康检查（确认组件正常运行）
4. 如果任何阶段失败，自动使用之前的版本进行回滚
5. 回滚成功 → 标记为 **已回滚**
6. 回滚失败 → 标记为 **失败**

## 常见问题

### Q: 升级失败，如何查看原因？

进入任务详情，查看 **集群明细** 中失败集群的 **信息** 字段。也可查看升级 Pod 的日志：

```bash
kubectl logs -n rlark-system <upgrade-pod-name>
```

### Q: 升级过程中可以取消吗？

当前不支持取消。可以删除 UpgradeJob，但已开始的升级会继续执行。

### Q: 回滚会恢复配置吗？

回滚使用上次升级成功时记录的配置，包括镜像和部署配置。

### Q: 如何修改控制面地址？

在 **部署配置** 中填写新的地址：

```yaml
control-plane-address: https://new-server:8443
```

### Q: 多个集群同时升级失败怎么办？

每个集群独立执行升级和回滚。失败的集群会根据配置决定是否回滚。可在详情页查看每个集群的具体状态。
